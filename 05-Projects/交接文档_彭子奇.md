# 2 订单系统重构
## 2.1 新架构
这部分内容在 `canrd-erp` 的 `docs/ARCHITECTURE_GUIDE.md` 中已有详细描述，这里仅做一些补充说明。

**当前这套架构并非纯血 DDD**
- 纯血 DDD 会有一个 application 层，其作用是编排 domain 和 repository 来实现完整的业务需求。但由于本系统使用工作流来编排业务，实质上替代了 application 层的功能，因此在设计架构时便将其省略。
- 纯血 DDD 要求各领域之间不能直接调用，而是通过领域事件进行通信。但目前的设计中，domain 之间是直接调用的。据我了解，DDD 这样做主要是为微服务拆分做准备，以便将来更方便地划分微服务。然而以我们公司目前的团队规模，将订单系统拆成微服务的可能性不大；加上引入领域事件需要依赖 Redis 或 Kafka 等中间件，会增加系统复杂度，我认为当前阶段没有必要这样做。

## 2.2 工作流
这部分内容在 `canrd-erp` 的 `docs/WORKFLOW_GUIDE.md` 中已有详细描述，这里仅做一些补充说明。

**个人建议**
- 如果订单流程至今仍在频繁变动，其实并不适合用 XML 重构为工作流。因为流程变动频繁意味着每次改动的成本会比重构前更大 —— 不仅要修改 XML 文件，还要处理改动前后的适配问题。
- 推荐安装 IDEA 插件 [LiteFlow-Helper](https://plugins.jetbrains.com/plugin/index?xmlId=com.yomahub.LiteFlow-Helper&utm_source=product&utm_medium=link&utm_campaign=IU&utm_content=2026.1)，可以在右侧窗口快速跳转到对应节点，也能从节点快速跳转到对应的组件。

数据库的部分表结构可能存在不够合理的地方，某些字段也可能是冗余或无用的，后续如果需求任务不多的话，可以考虑优化。

# 3 科言猫书籍下载
书籍下载的脚本文件及已下载的书籍源文件均存放在 243 服务器的 `/mnt/DATA/book-files` 目录下。目录结构如下：

```text
/mnt
└── DATA
    └── book-files
        ├── ia_downloads/       # IA 书籍下载目录（源文件）
        ├── ia_resume/          # IA 下载缓存目录（用于断点续传）
        ├── ia_torrents/        # IA 种子文件目录
        ├── libgen_downloads/   # LibGen 书籍下载目录（源文件）
        ├── libgen_resume/      # LibGen 下载缓存目录（用于断点续传）
        ├── libgen_torrents/    # LibGen 种子文件目录
```
