# 方法层（怎么写笔记）
## Zettelkasten 卡片盒笔记
Zettelkasten（德语：卡片盒）由尼古拉斯·卢曼（Niklas Luhmann）发展。它不是单纯的存储信息的笔记工具，而是让你与自己的思想持续对话的系统，目的是激发你的灵感。

**示例网站**：
- https://notes.andymatuschak.org/About_these_notes
- https://github.com/jorgealves/obsidian-vaults/tree/main
- https://github.com/deathau/sliding-panes-obsidian

**核心原则**：
- One note, one idea（一张卡片只表达一个完整想法）
- 用自己的话重述，而非复制粘贴
- Zettelkasten 应该只存放思考类的笔记（可以演化、可以被引用、可以与其他想法产生碰撞），非思考类内容（纯事实、摘录、待办）不要放进永久笔记，因为它天然就是独立文档，不会与其他文档产生关联

**笔记生命周期**：
1. **Fleeting Notes（临时/闪念笔记）**
    - 快速捕捉灵感、想法、灵光一现
2. **Literature Notes（文献/素材笔记）**
    - 对原始来源（书、文章、视频、课程）的加工提炼，用自己的语言总结关键观点、论据、例子
3. **Permanent Notes（永久笔记）**
    - 从 Literature 中提炼出的独立、可链接的思想，必须是「你自己的观点」或「经过验证的洞见」
    - **重要**：Literature 原文保留，不因重复而删除
    - 命名要精确（见 Evergreen 部分）

> 注意 ：
> - 从 Literature Notes 提炼观点到 Permanent Notes 后，Literature Notes 的原内容依然保留
> - Permanent Notes 不需要做文件夹分类，因为知识其实是互通的，一张卡片可以同时属于多个分类

**链接与关系说明**：链接笔记时，必须说明关系，例如
```
- [[确认偏差]] - 偏见如何影响决策
- [[时间压力效应]] - 紧迫感如何改变决策质量
- [[团队动态]] - 团队与个人决策的差异
```

### Evergreen Notes（常青笔记）
常青笔记是 Andy Matuschak（前 Apple 工程师）在 2019 年提出的笔记方法论，深受 Zettelkasten 启发，可以说是为数字时代重新诠释的 Zettelkasten。

**特点**：
- Permanent Notes 的名称必须是一个清晰可检验的主张、可以被反驳的观点
- 必须与其他笔记有明确关联（无孤立笔记）
- 随认知更新而演化（不是写完就封存）

**案例**：
- ✅
	- 反馈的效力随时间间隔指数衰减
	- 主动倾听要求暂时悬置自己的判断
	- 冲突中先命名情绪再讨论事实更容易被接受
- ❌
	- 情商的五大体系
	- 驾驶理论
	- 中医理论

> 常青笔记的比喻来自园艺：常青树不会随季节枯萎，笔记也应随你的理解不断生长。

# 组织层（笔记放哪里）
## PARA
PARA 是 Tiago Forte 提出的行动导向组织系统，按信息对行动的支持程度分类，而不是按主题。

|分类|全称|含义|特点 / 示例|维护频率|
|---|---|---|---|---|
|**P**|Projects|有明确目标和截止时间的项目|写一篇博客、准备季度汇报、装修房子|高|
|**A**|Areas|必须持续维护的长期责任领域|健康、财务、职业发展、家庭|中|
|**R**|Resources|感兴趣或未来可能用到的资源|设计灵感、工具收藏、行业报告|低|
|**A**|Archives|已完成、休眠或失效的内容|旧项目、过期资料|极低|

**判断流程**：
- 有明确截止日期和目标？→ Projects
- 需要持续关注否则会出问题？→ Areas
- 未来可能有用？→ Resources
- 已完成或不再相关？→ Archives

# 导航层（怎么找到笔记）
## MOC
MOC（Map of Content，内容地图）是自下而上构建的主题导航入口。它不是一开始就建立的，而是当某个领域笔记积累到一定量时，手动策划而成。

**特点**：
- 手动组织（体现你的理解）
- 可以包含评论、导读、主观判断
- 可以同时链接 Permanent Notes 和 Literature Notes

**示例**：
```
# 机器学习 MOC

## 基础概念
- [[监督学习]]
- [[无监督学习]]
- [[损失函数]]

## 算法
- [[线性回归]]
- [[决策树]]
- [[神经网络]]

## 实践
- [[模型评估]]
- [[特征工程]]
```

# 落地方案
## 分类
- Tags：用于广义检索
- Links：用于表达具体关系
- Folders：PARA 为主，知识笔记可轻量使用

## Ontology 本体字段

|字段|含义|推荐判断问题|示例|
|---|---|---|---|
|**parent**|上位概念|它属于什么？|确认偏差 → 认知偏差|
|**children**|下位概念|它可以拆成什么？|认知偏差 → 确认偏差、锚定效应|
|**requires**|前置知识|理解它之前必须知道什么？|损失函数 → 微积分基础|
|**similar**|同类思想|还有什么在解决类似问题？|确认偏差 → 可用性启发|
|**opposes**|对立观点|什么观点与它相反？|成长型思维 → 固定型思维|
|**source**|来源|我是从哪里学到的？|书名、文章链接|
|**author**|提出者|是谁提出或主要传播了它？|卡罗尔·德韦克|
